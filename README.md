# OII ranking

Builds the videos of the award ceremony of the OII: one video per medal, where every contestant appears with photo, school, a timelapse of their screen and score, and the medal. Recap pages summarize groups of contestants.

It is a single Rust program. Text is typeset with New Computer Modern (the LaTeX font, built into the binary), and frames are rendered in parallel and streamed to ffmpeg.

## Requirements

- [Rust](https://rustup.rs) (to build) and `ffmpeg` (to encode). Nothing else: no Python, LaTeX, ImageMagick or asymptote.
- A ranking file `./ranking.csv` with columns: `position`, `username`, `name`, `school`, `city`, `province`, `medal`, `class`, `po`. If the `po` column is missing, no participant will be considered a PO. Position can be empty for unofficial contestants.
- A folder with the cmsRankingWebServer or terry or quizms data (`./ranking/`, mandatory).
- A folder with all the faces (`./faces/username.jpg`, or png/webp). Missing faces are replaced by a placeholder.
- A folder with all the screenshots (`./screenshots/username/date.png` or `date.jxl`, e.g. `2026-09-25T10:28:03.123456.jxl`; PNG and JPEG XL can be mixed, and the accepted extensions are set by `paths.screen_extensions` in `config.toml`). If the screenshots of a user are missing, a placeholder is used instead. If all screenshots are missing, placeholders (a clock for every minute of the contest) are generated by `preprocess` when `./screenshots/background.png` and `./screenshots/filler.png` are given; this is skipped if files matching `20*00.0.png` are already in `./screenshots/`.

## Build

```
cargo build --release
```

The program is `target/release/oii-ranking` (copy it anywhere, or use `cargo install --path .`). The commands below assume it is on the `PATH`. Every command works on the current directory; use `-C <dir>` to work on another one (`oii-ranking -C ../data render gold`).

## Quick test with placeholder data

```
oii-ranking make-test-data    # creates ranking.csv, ranking/, faces/, screenshots/ (15 fake users)
oii-ranking preprocess
oii-ranking render all -q l   # a few seconds
```

`make-test-data` refuses to run if any of those paths already exists, so it will not overwrite real data. All generated paths are git-ignored.

If the raw export is in `./orig` (`temp.csv` and `faces.zip`), `oii-ranking import-orig` converts it into `ranking.csv` and `faces/`.

## Preprocess data

```
oii-ranking preprocess      # cms data
oii-ranking preprocess -t   # terry and/or quizms data
```

This writes `./output/`: the score history of every contestant, the ranking, and the faces cropped to a centered square in `./output/faces`. The crop is not perfect and can be tuned by replacing the images in that folder: `preprocess` does not overwrite them.

## Render

```
oii-ranking render <gold|silver|bronze|mention|all> [-q l|m|h|p|k] [--wide]
```

- `-q` is the quality, as in manim: `l` 854x480 15fps (preview), `m` 720p30, `h` 1080p60 (the default, final), `p` 1440p60, `k` 2160p60.
- `--wide` renders the 64:9 version (7680x1080 at `-q h`; only `l`, `m`, `h`), with its own settings in the `[wide]` section of `config.toml`.
- Videos go to `media/rust/<standard|wide>/<height>p<fps>/<Medal>.mp4` (or `-o <file>`). A video is written to `<Medal>.partial.mp4` and renamed when complete, so an interrupted render never replaces a good video.

To iterate on a detail without rendering everything:

```
oii-ranking still gold --at 12.5 -o frame.png      # one frame, instantly
oii-ranking render gold -q l --only gambaro,bamber  # only some contestants (no recap pages)
oii-ranking render gold --from 60 --to 75          # a part of the video, in seconds
```

While rendering, the video is shown in a window (with `ffplay`, which comes with ffmpeg), as fast as it is rendered. `--preview realtime` plays it at its real speed instead, slowing the render down if it is faster, and `--preview off` shows nothing. Closing the window does not stop the render; without a display or `ffplay`, the render goes on without the window.

There is no cache to clean: every render starts from the data.

Rendering time on a 16-core laptop (Ryzen 9 6900HX), encoding on the CPU with x264: the gold video (2.5 minutes, 9 contestants) takes about 50 seconds at 1080p60 and about 2.5 minutes for the 7680x1080 version. About half of the time goes into the encoder, and most of the rest into decoding the JPEG XL screenshots of the timelapses (one per frame). Encoding on an AMD GPU (RX 6650M) makes the 7680x1080 version about 1.6 times faster.

## Hardware encoding

Encoding on the GPU leaves the CPU free for drawing the frames. By default (`video.hardware = "auto"` in `config.toml`) the program finds the GPUs by itself: NVIDIA cards (through NVENC) first, since they are usually the faster, then AMD and Intel ones (through VAAPI). Before rendering, it encodes a few test frames of the video's size on each, checks that they decode at the right size, and uses the first GPU that passes: H.264, or HEVC for videos wider than 4096 pixels (the most H.264 hardware encoders accept), such as the 7680x1080 version. It prints which encoder it uses and, when no GPU works, why. Set `video.hardware = "off"` to never use the GPU, or to a device (e.g. `"/dev/nvidia0"` or `"/dev/dri/renderD128"`) to test only that one.

**Fallbacks.** When no GPU passes the test, the encoder of `video.encoder` is used (x264 by default, on the CPU). If the GPU fails during a render, the video is rendered again with that encoder. If ffmpeg lacks it (Fedora's default ffmpeg has no x264), `libopenh264` is used instead, up to 4096 pixels of width.

All the GPU needs is the right driver, below; nothing has to be set in `config.toml`.

### AMD

The GPU needs the VAAPI driver of Mesa with the H.264 and HEVC encoders:

| Distribution | Command |
|---|---|
| Ubuntu | `sudo apt install mesa-va-drivers vainfo` (usually already installed) |
| Fedora | Fedora's own Mesa lacks the encoders (for patent reasons): take RPM Fusion's.<br>`sudo dnf install https://mirrors.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm`<br>`sudo dnf swap mesa-va-drivers mesa-va-drivers-freeworld`<br>`sudo dnf install libva-utils`<br>(to undo: `sudo dnf swap mesa-va-drivers-freeworld mesa-va-drivers`) |
| Arch | `sudo pacman -S mesa libva-utils` (the VAAPI driver is part of `mesa`; on older installs it is the separate `libva-mesa-driver`) |

Without the encoders the program reports `Compatible profile ... is not supported by driver` and uses the CPU. To check the driver: `vainfo --display drm --device /dev/dri/renderD128 | grep EncSlice` should list `VAProfileH264High` and `VAProfileHEVCMain` (if there are several GPUs, the others are `renderD129`, ...).

### NVIDIA

The GPU needs NVIDIA's proprietary driver (it contains the encoder library, `libnvidia-encode`):

| Distribution | Command |
|---|---|
| Ubuntu | `sudo ubuntu-drivers install`, then reboot |
| Fedora | Enable RPM Fusion free and nonfree (see [rpmfusion.org](https://rpmfusion.org/Configuration)), then `sudo dnf install akmod-nvidia xorg-x11-drv-nvidia-cuda-libs` and reboot |
| Arch | `sudo pacman -S nvidia-open nvidia-utils` (or `nvidia` for cards older than the GTX 16xx series), then reboot |

Without the driver the program reports `Cannot load libcuda.so.1` and tries the next GPU. The 7680x1080 videos (HEVC that wide) need a GTX 10xx card or newer. To check the driver: `ffmpeg -f lavfi -i testsrc2=size=7680x1080:rate=60 -t 2 -c:v hevc_nvenc -f null -` should end without errors.

### ffmpeg

The ffmpeg of Ubuntu and Arch has everything (x264, VAAPI, NVENC): `sudo apt install ffmpeg` or `sudo pacman -S ffmpeg`. Fedora's default ffmpeg (`ffmpeg-free`) has VAAPI and NVENC but no x264, so without a GPU the videos are encoded with `libopenh264`, of lower quality; RPM Fusion's ffmpeg has x264: `sudo dnf swap ffmpeg-free ffmpeg --allowerasing`.

A 7680x1080 HEVC video needs a player (and a machine) that can decode HEVC that wide: check it on the computer that will play it.

## Settings

`config.toml` has all the settings, with comments: contest days and maximum score, timing, medal groups, paths, colors, fonts, the class names and the encoder. Keys left out take the default value (the version of the file in this repository is built into the binary), so a data folder can have a `config.toml` with just the settings it changes.

Medal groups are `[columns, rows, scale]`, optionally followed by the number of contestants in the group (by default `columns * rows`). A recap page is shown after each group; an empty list means no recap pages. Mentions use exactly one group, whose size does not have to match the number of mentions.

## Overlays

Transparent overlays (ProRes 4444 `.mov`) for the live stream:

```
oii-ranking overlay countdown 10
oii-ranking overlay name-marker "Name Surname" "Title"
```

They use the fonts OCR A Extended and Futura if they are installed.

## Differences from the manim version

The videos have the same timing, frame by frame, and the same layout. Other changes:

- Multi-day contests: the timelapse now shows each day completely (it used to show only the first part of each day when there were several days).
- Faces are rotated according to their EXIF orientation when cropped.
- Built-in placeholders are used when `images/noface.jpg` or `images/circuits.png` are missing, and built-in copies of the logo, medal and cup when those files are missing.
- The overlays take their text as arguments instead of asking for it.
